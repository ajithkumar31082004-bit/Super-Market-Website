Overview

SuperMarket Pro is a high-availability, cloud-native supermarket application designed to handle high-concurrency retail transactions, dynamic shopping cart sessions, inventory tracking, asset management, and serverless order processing.

  • Who it is for: Modern retail chains and grocery brands seeking automated digital storefronts, real-time inventory management, and zero-downtime deployment pipelines.
  • Why it was built: To replace monolithic legacy grocery systems with an elastic, microservice-based architecture that scales automatically during peak shopping hours.
  • Core Objective: Combine serverless AWS compute with a fully automated CI/CD pipeline (**AWS CodePipeline**, **AWS CodeBuild**, **Amazon ECR**, and **Amazon ECS Fargate**) for zero-touch deployment.

High-Level Architecture Model

The platform relies on a hybrid datastore strategy: dynamic cart states reside in low-latency **Amazon DynamoDB**, catalog transactions sit in **Amazon RDS MySQL**, and media uploads stream straight to **Amazon S3**.

Orders trigger asynchronous serverless **AWS Lambda** processors that dispatch SMS/Email updates via **AWS SNS**, while **Gemini AI** generates smart product recommendations for shoppers.

Build & Packaging Stage

Code changes trigger an AWS CodePipeline execution via GitHub webhook. AWS CodeBuild reads the custom buildspec.yml to run unit checks, authenticate with Amazon ECR, and build optimized multi-stage Docker images tagged with Git commit SHA and latest.

Serverless Deployment Stage

CodeBuild pushes container image tags to Amazon ECR registry and updates the Amazon ECS Task Definition. ECS executes a rolling deployment on serverless Fargate tasks behind an Application Load Balancer, guaranteeing zero downtime.

The Problem

Traditional supermarket e-commerce setups face severe infrastructure constraints:

  • Manual Deployment Bottlenecks: SSH-based manual server updates cause service downtime and human deployment errors.
  • Cart Session Latency: Storing cart states in relational databases creates locks and slows checkout response times.
  • Static Infrastructure Costs: Over-provisioned EC2 instances run 24/7 even during off-peak night hours.
  • Unsynchronized Stock Data: Slow database queries cause out-of-stock items to remain orderable on storefronts.

The Solution

SuperMarket Pro delivers cloud automation and instant scalability:

  • Zero-Downtime AWS CI/CD: Automated pipeline pushes verified Docker containers from GitHub to ECS Fargate in minutes.
  • Sub-Millisecond DynamoDB Caching: Shopping cart items store in DynamoDB for instant add/remove responsiveness.
  • Serverless Pay-per-Use Runtime: ECS Fargate automatically scales container instances up or down based on traffic load.
  • Asynchronous Lambda Order Processing: AWS Lambda and SNS handle post-checkout tasks without blocking customer UI.

Engineering Challenges

How specific cloud configuration, buildspec, and database parity challenges were solved.

ECR Docker Authentication in CodeBuild

Problem

AWS CodeBuild phase failed to push built container images to Amazon ECR due to standard Docker login permission drops.

Solution

Configured AWS STS caller identity in buildspec.yml and fetched dynamic login passwords using AWS CLI before build phases.

Outcome

Achieved seamless, automated container builds and pushes to ECR tagged with Git commit SHAs.

High-Concurrency Cart State Locking

Problem

Storing user cart session states in MySQL created table locks and dropped requests under concurrent add-to-cart operations.

Solution

Decoupled cart states into Amazon DynamoDB key-value tables indexed by unique session tokens with local storage fallbacks.

Outcome

Reduced cart interaction response latency to under 5ms and eliminated database lock contention completely.

Zero-Downtime ECS Fargate Task Updates

Problem

Updating live container deployments caused temporary 502 Bad Gateway errors while old containers terminated.

Solution

Configured ECS Service rolling deployment parameters with Application Load Balancer target group deregistration delays.

Outcome

Ensured new container tasks pass health checks before traffic shifts, guaranteeing 100% continuous uptime.
